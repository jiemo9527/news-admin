# News Admin

多来源新闻 → 结构化分析 → 事件聚类 → 带引用的中文摘要 → 排序 → Web 简报 + 多渠道推送。

大模型负责理解、归纳和判断；结构化输出经过 Schema 校验，摘要经过引用与数字证据检查，不合格则重试或中文要点降级。这些检查不是完整语义事实验证，不承诺零幻觉。

```
抓取 ─► 去重 ─► 逐篇分析(LLM) ─► 价值过滤 ─► 事件聚类(向量+LLM) ─► 前序关联(向量+LLM) ─► 排序 ─► 摘要(LLM)+事实校验 ─► 配图 ─► 发布/推送
```

设计原则、阈值和取舍见 [docs/DESIGN.md](docs/DESIGN.md)。

## 各环节怎么做

| 环节 | 做法 | 为什么 |
|---|---|---|
| 抓取 | 四种来源类型：RSS、JSON Feed、央视列表接口、网页列表页（只需一个文章链接正则）；标题/时间/正文用通用元数据与 trafilatura 抽取，失败退回列表摘要 | 旧版为每个站点手写上千行选择器和特例；v2 换站点只改配置 |
| 一级去重 | 规范化 URL 精确去重 + 字符 3-gram 包含度 ≥0.8 判为通稿转载 | 不花模型钱；短文本上比 SimHash 稳定 |
| 价值过滤 | 分析阶段标注内容类型（新闻/评论/科普特写/宣传）、是否有新进展、对读者的实际意义 1-5；科普/历史类且无新进展、宣传类、影响力 <2 的不进简报，过滤原因在后台可查 | 「长江名称历经演变」这类文章不该出现在简报里；规则确定、可调、可审计，误杀能看到 |
| 分类 | 地区（国内/港澳台/国际/全球）和主题（10 类）**两个独立维度**；置信度 <0.5 归「其他」 | 旧版把地区和主题混在一个字段，「中国芯片出口管制」只能二选一 |
| 同一事件 | 用 LLM 归一化后的「中文标题+事件指纹+关键事实」做向量；≥高阈值直接合并，模糊区间交给 LLM 按「主体+行为+时间地点」判定，48 小时窗口 | 中英文报道原文的向量相距很远；判定标准写死，评论文章不与事实报道合并 |
| 连续性 | 与近 7 天已发布事件比对：同一事件无新报道 → 不再推送；同一事件有新报道 → 标「更新」；同一故事线的新进展（制裁→反制、降息→股市大涨）→ 标「后续」并引用前序报道，事件共享故事线 ID | 读者能顺着链接看到来龙去脉；候选先用向量+共同实体筛，再由模型判断关系，控制调用量 |
| 时间 | 每篇记录发布时间、更新时间和精度（精确到分 / 只有日期 / 未知）；显示为「3小时前 · 10-17 17:00」，只有日期的显示「今天」，绝不编造时刻 | 新闻的价值高度依赖时效，模糊时间必须如实标出 |
| 配图 | RSS media/enclosure、列表接口图片、文章页 og:image；排除 logo/图标/占位图；下载后缩放为 480×320 WebP 本地缓存，经 `/thumb/<key>` 提供 | 避免防盗链破图和向第三方泄露访问；单图约 10-30 KB |
| 摘要 | 每句必须带来源编号；句中数字必须能在**所引用的那篇来源**中找到；禁止套话；来源说法冲突时单独列出 | 让摘要可追溯，减少编造 |
| 排序 | `影响力×2 + log2(1+来源数)×1.5 + 新鲜度 + 来源权重 − 评论类惩罚` | 可解释；来源数边际递减，避免转载多就排前面 |

### 结构化输出

- 所有模型输出由 Pydantic 定义（`news_admin/models.py`），自动转换为 OpenAI strict JSON Schema（内联 `$ref`、全部字段必填、禁止额外字段）
- 网关不支持 `json_schema` 时自动降级为 `json_object` + 本地校验
- 校验失败把 Pydantic 报错原文回传给模型重试，最多 2 次
- 以「模型 + Prompt 版本 + 输入」为键缓存结果，改 Prompt 必须提升版本号（`news_admin/prompts.py`）
- 每次调用记录阶段、Token、耗时、重试、是否命中缓存，后台按运行汇总

## Docker Compose（推荐）

`main` 为当前正式版本（v2 重写应用），旧 v1 不再维护。镜像：`ghcr.io/jiemo9527/news-admin:latest`，目标 `linux/amd64`。详细说明见 [DEPLOYMENT](docs/DEPLOYMENT.md)、[OPERATIONS](docs/OPERATIONS.md) 和 [CHANGELOG](CHANGELOG.md)。

```bash
mkdir -p data
sudo chown -R 10001:10001 data
cp .env.example data/config.env
sudo chown 10001:10001 data/config.env
sudo chmod 600 data/config.env
docker compose up -d
docker compose logs news-admin
```

首次管理员账号和密码只打印启动日志，已有账号不重置。默认只绑定 `127.0.0.1:5080`；公网访问在 Compose 参数 `.env` 设置 `NEWS_BIND=0.0.0.0`，推荐 HTTPS 代理，不要长期通过裸 HTTP 传输密码。

容器以非 root 用户 `10001:10001` 运行。`./data:/app/data` 包含数据库、图片、缓存及后台可编辑配置 `config.env`。`NEWS_ENV_PATH` 指定配置文件，裸机默认为仓库 `.env`。不要只读单文件挂载配置；不要在 Compose environment 重复填写模型变量，否则会覆盖后台保存值。一次只跑一个实例、一个 worker。

GitHub Actions 在 main 推送后运行测试、镜像构建和新装容器冒烟检查，再发布 GHCR 的 latest 与 sha-完整提交标签。生产建议固定 digest。数据、密钥与本地 agent.md 均排除在 Git 和构建上下文之外。

## 本地快速开始

```bash
uv venv && uv pip install -e ".[dev]"
cp .env.example .env        # 填写模型和向量服务
python -m news_admin run --no-push   # 跑一次，不推送
python -m news_admin show            # 终端查看最新简报
python -m news_admin serve           # http://127.0.0.1:5080
```

`.env`：

```ini
NEWS_LLM_BASE_URL=https://api.openai.com/v1   # 任意 OpenAI 兼容接口
NEWS_LLM_API_KEY=
NEWS_LLM_MODEL=gpt-5.6-luna
NEWS_EMBEDDING_BASE_URL=https://api.siliconflow.cn/v1
NEWS_EMBEDDING_API_KEY=                       # 不填则降级为字符哈希向量
NEWS_EMBEDDING_MODEL=BAAI/bge-m3
NEWS_ADMIN_PASSWORD=                          # 不填则首次初始化随机生成并打印到启动日志，不生成 TXT
NEWS_PUBLIC_BASE_URL=                         # 推送消息中的简报链接
```

## 来源预置

预置来源包括：路透社（buzzing.cc 中文 JSON Feed）、BBC、纽约时报、CNN、央视新闻（国内/国际两个接口）、新华社、人民网、RT、联合早报。
另有 BBC 中文、德国之声中文、法广中文、中新网、卫报、半岛电视台等 RSS 备选（`news_admin/sources.py` 的 `EXTRA_SOURCES`），可在后台添加。

## 时间

全系统统一为北京时间（Asia/Shanghai，UTC+8）：数据库时间戳、页面显示、Cron 定时、抓取时间窗、日志都按东八区。
旧版本按 UTC 存的时间戳在启动时自动改写。

## 账号与页面

所有页面都需要登录，未登录只能看到登录页。两种角色：

- **管理员**：全部功能
- **只读用户**：可浏览新闻、往期简报和后台各页面；不能运行、修改或删除（服务端对所有写操作返回 403），只能改自己的密码

首次启动自动创建管理员 `admin`，随机初始密码只打印在启动日志，不生成 TXT 文件（或用 `NEWS_ADMIN_PASSWORD` 指定）。
「用户管理」中新增用户时自动生成用户名和 20 位强密码（不含 0/O、1/l/I 等易混淆字符），只显示一次，可一键复制；
登录、登出、登录失败和页面访问都记录时间、IP、设备（同一用户同一 IP 30 分钟内的访问合并为一行）。
部署在反向代理后面时设 `NEWS_TRUST_PROXY=true`，才会采用 `X-Forwarded-For` 中的客户端地址。

- `/`：新闻汇总。所有期次的事件合并成一条时间线，同一事件只显示最新版本；输入关键词即时筛选（不用点搜索），
  可按新闻来源、时间范围（今天 / 昨天 / 3天内 / 一周内）、主题筛选，按最新或评级排序，每页 20 条
- `/briefs`：往期简报，每期收录评级最高的 50 条（可调）；其余事件同样入库，在首页汇总中可见
- `/admin`：概览、运行记录（失败记录可删除）、立即运行、定时
- `/admin/sources`：来源卡片（健康度、测试抓取、编辑、停用、删除）+ 推荐来源一键添加
- `/admin/channels`：Telegram / 钉钉 / 飞书 / 企业微信 / 邮件推送
- `/admin/users`：用户管理与登录访问记录（仅管理员）
- `/admin/settings`：抓取时间窗、保留天数、修改密码；**模型与向量**（接口地址、模型名、API Key、并发、合并阈值、最低影响力、每期简报条数）
  在页面上修改后写回 `.env` 并立即生效，可一键测试连接

## 抓取与保留

- 抓取范围支持「昨天和今天」「最近 24 小时」「7×24 小时内（低速模式）」。低速模式自动单线程，HTTP 请求间隔 3–6 秒（含跳转）；403/429 停止当前来源，不重试。
- 每源条数上限仍有效（默认 10），选择一周不代表补齐整周所有新闻：来源列表不提供的旧闻无法回溯。遵守来源使用条款，不绕付费墙。
- 与近 7 天已入库事件比对，同事件不重复入库和推送。
- 历史保留 90 天：每次运行后自动删除更早的运行、事件和缩略图

## 评测

```bash
python -m news_admin export-eval <run_id> --output eval/data/to_label.jsonl  # 导出待标注
# 人工填写 gold_region / gold_topic / gold_event
python -m news_admin eval --data eval/data/to_label.jsonl --output eval/report.json
```

输出地区/主题准确率与混淆、聚类成对 Precision/Recall/F1、摘要首轮通过事实校验的比例，以及 Token 用量。用来对比模型、Prompt 版本和聚类阈值。

## 独立的抓取与推送计划

概览页中分别设置两种 Cron（均为 Asia/Shanghai）：

- 定时抓取：保留已有配置，例如 `2 */2 * * *`，每两小时第 2 分钟抓取、入库和生成简报；不推送。
- 简报推送：默认 `0 6,20 * * *`，每天 06:00 / 20:00。汇总自每个渠道上次成功发送以来的多个抓取批次，事件取最新版本后按分数选前 `NEWS_MAX_EVENTS` 条（默认 50）。未选入的仍在库中，不排队补发。第一次推送覆盖最近 24 小时。
- 各渠道只有发送成功才前移进度，失败可在下一次计划重试；没有新结果时不发送。
- 后台「立即运行」只抓取，不推送；运行详情的「重新推送」仍可手动发送该期。

## 手动备份、恢复与清空

仅管理员可使用「数据管理」：

- 手动导出 ZIP：包含 SQLite 快照、模型 `.env` 配置、用户密码哈希、推送渠道和密钥、来源、记录、新闻与缩略图；不含日志、缓存。备份含敏感信息，不要公开。
- 恢复：输入当前管理员密码，上传 ZIP。先检查路径、大小、文件哈希、数据库完整性/结构、账号、Cron 等；失败回滚。成功后旧会话失效，使用备份中的账号重新登录。
- 清空：输入当前管理员密码。删除新闻、简报、运行/访问/推送记录、普通用户、缓存和缩略图；**所有管理员账号及密码、来源、渠道、模型和计划设置保留**。
- **不会自动生成备份**，恢复、清空前需自行手动导出。恢复失败回滚使用内存中的临时事务状态，不留备份文件。
- 抓取/推送期间拒绝备份、恢复和清空，避免并发损坏。

简报分类栏保持吸顶，点击分类或继续滚动时标出当前栏目，移动端可横向滑动切换。


### 精简推送格式

所有渠道（Telegram、钉钉、飞书、企业微信、邮件）正文第一行是简报 URL，之后只含新闻标题、评级和综合权重分；不发送摘要、来源、时间或前情。长消息每段首行重复链接。网页完整内容不变，仍须登录。

在「系统设置 → 模型与向量 → 推送链接」设置网站公网根地址（`NEWS_PUBLIC_BASE_URL`，例如 `https://news.example.com`）。未配置则记录推送失败，不发无链接消息，不推进渠道游标。手动推送指向对应期次；定时推送生成持久化汇总快照，覆盖该次实际选中的所有事件，而非仅链接最后一期。快照随关联运行的保留期清理，包含于手动备份；旧版不含快照表的备份仍可恢复。
