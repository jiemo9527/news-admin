# 运维手册

## 常用命令

```bash
docker compose ps
docker compose logs --tail=100 news-admin
curl -fsS http://127.0.0.1:5080/healthz
docker compose restart news-admin
```

首次初始化日志含敏感随机密码。以后忘记密码请由其他管理员在用户管理中重置，或在维护窗口使用配置 `NEWS_ADMIN_PASSWORD` 指定管理员密码再重启；使用后去掉明文启动密码并在后台改密。

## 后台入口

- 概览：抓取计划、推送计划、运行记录；失败/中断运行可删除。
- 新闻来源：卡片、单源测试、编辑、启停、删除；推荐来源可重新添加。
- 系统设置：抓取时间窗、保留天数、模型/向量/阈值、密码。
- 数据管理（数据库小图标）：手动 ZIP 导出、恢复、清空；不自动备份。
- 用户管理：生成只读或管理员账号、复制初始凭据、停用/角色/改密/删除；访问记录只保存时间、IP、设备，不记录密码。

## 7×24 小时低速抓取

系统设置选择“7×24 小时内（低速模式）”。服务端会自动启用串行请求、3–6 秒间隔、403/429 中止来源。预计比普通模式慢，来源当前页没有历史时无法补齐。仍限制每源条数，不自动扩到几百条。不要把低速模式描述为保证不会风控。

## 问题排查

- 账号登录失败：确认用户启用、角色、密码；重置后旧会话失效。
- 无新闻：查看抓取窗口、来源是否启用、来源健康、过滤原因、模型调用错误。
- 容器启动失败：检查 `data/` 权限是否 10001，`config.env` 是否可写，5080 是否被占用。
- 缺图：外站没提供图片、图标过滤、下载失败等都会导致无图，新闻不因此丢弃。
- 不推送：检查独立的推送计划、渠道启用与凭据、是否有未成功发送的新结果。抓取计划不控制推送频率。
- 后台改模型重启后失效：不要在 Compose `environment` 覆盖模型字段，确保 `NEWS_ENV_PATH` 指向持久化目录。
- 403/429：停止对应来源本轮抓取，缩小数量/频率，不绕过 WAF。
- 时区：统一 Asia/Shanghai；容器 `TZ` 只作为系统工具一致性配置，业务时间使用 zoneinfo。

## 数据维护

手动导出 ZIP 后妥善离线保管。恢复包含敏感密钥，不能拿不可信 ZIP 覆盖生产数据。恢复支持当前 schema 包，跨旧版本需先升级并验证。恢复后需使用包内账号登录，所有旧会话失效。

清空不可撤销且不会自动备份。仅普通用户被删除，所有管理员保留。源、渠道、计划和模型设置保持。当前管理员密码校验仍必需，确认文字和弹窗按用户要求移除。


### 精简推送格式

所有渠道（Telegram、钉钉、飞书、企业微信、邮件）正文第一行是简报 URL，之后只含新闻标题、评级和综合权重分；不发送摘要、来源、时间或前情。长消息每段首行重复链接。网页完整内容不变，仍须登录。

在「系统设置 → 模型与向量 → 推送链接」设置网站公网根地址（`NEWS_PUBLIC_BASE_URL`，例如 `https://news.example.com`）。未配置则记录推送失败，不发无链接消息，不推进渠道游标。手动推送指向对应期次；定时推送生成持久化汇总快照，覆盖该次实际选中的所有事件，而非仅链接最后一期。快照随关联运行的保留期清理，包含于手动备份；旧版不含快照表的备份仍可恢复。


### 7×24 小时低速回溯（条数不设上限）

7 天模式忽略来源的 `max_items`，处理时间窗内来源公开提供的全部可获取候选；普通时间范围仍遵循每源条数。支持 JSON Feed `next_url`、RSS/Atom `rel=next` 和网页明确的“下一页”链接；同站点翻页，空页、重复页或整页已早于窗口即停止。Google News 来源按每天公开搜索覆盖 7 天，不再受原 URL 的 `when:1d` 限制。无公开历史入口的源只能取得其当前公开列表，不保证一周完整覆盖；不绕过付费墙或访问限制。单线程、每请求含跳转间隔 3–6 秒，403/429 停止该源并保留已取列表。

定时抓取只生成简报和入库，不自动推送；只有独立的简报推送计划到点才生成汇总快照并发送。手动推送仍由管理员明确操作。7 天全量可能显著增加耗时和模型费用。


### 抓取与推送（逻辑说明）

- 定时抓取 / 「立即抓取」 / `python -m news_admin run`：只抓取、入库、生成简报，**从不推送**。
- 简报推送（独立计划，默认 `0 6,20 * * *`）/ 「立即推送一次」 / `python -m news_admin push`：汇总该渠道上次推送后完成的所有批次（最多 48 小时），同一事件取最新版本、按评分取前 N 条。
- 每个渠道记录已推送的事件（`pushed_events`）：手动推送过的新闻、以及同一事件之后的「更新」版本都不会再被定时推送重复发送；没有新内容不发消息。
- 推送不等待正在进行的抓取，只汇总已完成的批次；手动推送、定时推送、命令行推送之间通过进程锁和数据库租约互斥。
- 运行详情的「手动推送本期」是管理员的明确操作，会再次发送整期（需确认），并记入推送历史。
- 推送渠道可在「推送渠道」页编辑、启停、发送测试消息；密钥只显示「已设置」，留空保持不变。
